# 競馬AIアプリ 設計書（v3順位分布モデル用）

## 1. 目的と要件

| 要件 | 決定事項 |
|---|---|
| 対象 | 中央平地・地方平地（障害・ばんえいは表示のみで予想しない） |
| レースの選び方 | 日付 → 競馬場 → R |
| 画面 | ブラウザ。出馬表の並び（枠・馬番・馬名・性齢・斤量・騎手・厩舎・馬体重）＋予想 |
| 予想の表示 | 各馬の着順ごとの確率を棒グラフ（行ごとの小グラフ・クリックで拡大）、レース全体のヒートマップ |
| 成績の追加・学習 | 自動（毎晩の成績追加、週1回の学習し直し） |
| 予想の記録 | 予想のたびに保存し、結果確定後に自動で照合・採点 |
| 外出先から | Tailscale（無料の個人プラン）で自分の端末だけから閲覧。サーバー料金なし |

## 2. 全体構成

```
自宅PC
├─ keiba_scraper   … netkeibaから一覧・出馬表・結果を取得（既存）   data\keiba.sqlite3, data\raw\
├─ keiba_ai        … prepare・v3パイプライン（既存）
└─ keiba_app       … 新規
    ├─ nightly     … 毎晩の自動処理（タスクスケジューラから起動）
    ├─ server      … ブラウザ用の画面とAPI（127.0.0.1:8765）
    └─ data\app\
        ├─ state.json        現在のDB・モデル・収集済みの日付
        ├─ app.sqlite3       予想の記録・照合結果・日別のレース一覧・実行履歴
        ├─ db\<日時>\features.sqlite3   prepare済みDB（新しい2世代を保持）
        ├─ models\<日時>\    v3モデル（新しい3世代を保持）
        └─ logs\             毎晩の処理のログ
外出先の端末 ──Tailscale（tailscale serve）──▶ 自宅PCの127.0.0.1:8765
```

* サーバーは外部に公開せず `127.0.0.1` だけで待ち受けます。Tailscaleの `tailscale serve` が、自分のアカウントの端末からの接続だけをHTTPSで中継します。
* 重い処理（取得・予想・更新）はサーバー内の作業キューで1件ずつ実行し、画面は進行状況を表示します。

## 3. 画面

### 3.1 開催一覧（日付 → 競馬場 → R）
* 日付の選択（前日・翌日ボタン付き）、中央／地方の切り替え。
* 競馬場ごとにRのボタン（発走時刻・レース名・予想済みの印）。
* 「レース一覧を取得」：その日の開催をnetkeibaの日別一覧から取得（中央・地方で2回の通信）。
* 「全レースの出馬表を取得して予想」：その日のすべての対象レースを一括で処理。

### 3.2 出馬表と予想
* 見出し：日付・競馬場・R・レース名・芝ダ距離・馬場・発走時刻・頭数・使ったモデル。
* 表：枠（色付き）、馬番、馬名、性齢、斤量、騎手、厩舎、馬体重（増減）、勝率、3着内率、期待着順、着順分布の小グラフ。結果が確定していれば着順も表示。
* 小グラフはレース内で同じ縦軸を使い、馬どうしを比べられるようにします。右端の灰色は競走中止。
* 行をクリックすると、その馬の大きなグラフ（各着順の確率を数値付き）を表示。
* ヒートマップ：馬（行）×着順（列）。
* 「予想する」／「最新の出馬表で予想し直す」：出馬表を取り直し（馬体重・取消を反映）、予想して記録。
* 予想の履歴：同じレースで複数回予想した場合は切り替えて表示。

### 3.3 予想の記録
* 期間（7日・30日・90日・全期間）と中央／地方で絞り込み。
* 指標：レース数、順位分布の対数損失（全馬同確率との比較）、1番手の馬の3着内率・勝率、1着の対数損失。
* 日ごとの対数損失の推移グラフ。
* 予想の一覧（日付・レース・1番手の馬とその着順・損失）。各行から出馬表の画面へ。
* 発走後に作った予想（過去レースのお試し）は「事後」として別扱いにし、成績の集計からは除きます。

### 3.4 状態
* 現在のDB（データ最終日）・モデル（学習期間・作成日時）・最後の自動処理の結果とログ。
* 「今すぐ成績を追加」「今すぐ学習し直す」ボタン（自動処理と同じものを手動で起動）。

## 4. 毎晩の自動処理（`keiba_app nightly`、既定は毎日2:30）

1. **成績の収集**：前回の収集日の翌日〜昨日を `keiba_scraper backfill`（中央・地方）。未完了なら収集日を進めず、次回に再試行（取得済みページは再取得しません）。
1. **血統の収集**：直近60日のレース（ばんえい除く）に出た馬のうち、血統が未取得の馬を `keiba_scraper pedigree --horse-id …` で取得。予想時にも、出馬表に未取得の馬がいればその場で取得します。
2. **CSV出力とprepare**：全期間を `export --page results` → `keiba_ai prepare --race-db`（新しいフォルダーに作成し、完成してから切り替え）。
3. **照合**：結果が出たレースについて、記録済みの予想を実際の着順で採点。
4. **学習し直し**（前回から7日以上たっていれば）：新DBで、今のモデルと同じ版（`pipeline_v4 fit --race-db`、旧モデルなら `pipeline_v3 fit`）。v4は混ぜ合わせの重みとネットワークの学習結果も確認。温度・反復回数などの健全性を確認してから切り替え。古いモデルは3世代保持。
5. **当日分の先行予想**：当日のレース一覧と出馬表を取得し、全対象レースを予想（馬体重発表前の暫定予想として記録）。
6. 実行結果を `app.sqlite3` とログに保存。失敗した段階があっても、前の段階の結果は残し、DB・モデルは完成したものだけに切り替えます。

成績を足すだけで、前走成績・スピード指数・レーティング・騎手θはすべて最新になります（モデルの学習し直しは不要）。学習し直しは週1回で十分です。

## 5. 予想の記録（app.sqlite3）

| 表 | 内容 |
|---|---|
| `predictions` | 予想ID、作成時刻、レースID、日付、地域、競馬場、R、発走時刻、モデル（train_end・作成日時）、DB、事前／事後、馬体重の有無 |
| `prediction_runners` | 予想ID×馬：馬番・馬名などの表示用情報、勝率・3着内率・期待着順・強さ、着順分布（JSON） |
| `outcomes` | 予想ID：照合時刻、実際の頭数、出走馬の一致、順位分布の対数損失・3着内・1着の対数損失、1番手の着順、全馬同確率の損失 |
| `day_races` | 日別一覧の取得結果（日付・地域・レースID・競馬場・R） |
| `runs` | 自動処理の実行履歴（段階ごとの成否・所要時間） |

* 出走取消などで予想時と実際の出走馬が違う場合は「出走馬が変わった」として、成績の集計から除きます。
* 集計には、各レースで発走前に作った最後の予想を使います。

## 6. 予想の仕組み（既存のv3パイプラインを利用）

* 出馬表はスクレイパーの保存データから取り出し、`normalize_row(page='entries')` で検査します。
* 履歴は予想日より前だけから作り直します（予想日の結果は使いません）。モデルの学習期間内の日付は予想しません。
* サーバー内でモデル・区分のデータ・日別の履歴をキャッシュし、同じ日の2レース目以降を速くします。DB・モデルが切り替わったらキャッシュを破棄します。
* 過去のレースは、保存済みの結果ページから着順・タイムを消して出馬表として使い、「事後」の予想として記録します。

## 7. 実装の順番

1. v3パイプラインの予想部分を、キャッシュ付きの `Predictor` に分割。
2. `keiba_app` の土台：設定・`state.json`・`app.sqlite3`・スクレイパー連携。
3. 毎晩の処理（収集・prepare・照合・学習し直し・先行予想）。
4. サーバーとAPI、作業キュー。
5. 画面（開催一覧・出馬表と予想・記録・状態）。
6. テスト（合成データで、取得を除く一連の流れ）、タスクスケジューラ登録スクリプト、README。

## 8. 使い方（初回）

```powershell
git pull
.\.venv\Scripts\python.exe -X utf8 -m pip install --no-deps --no-build-isolation -e .
# 既存のDBとモデルを登録（コピーはしません）
.\.venv\Scripts\python.exe -X utf8 -m keiba_app init --dataset data\ml_rank_bias_v2\features.sqlite3 --model-dir data\v3_model
# 画面を起動 → ブラウザで http://127.0.0.1:8765
.\.venv\Scripts\python.exe -X utf8 -m keiba_app serve
# 毎晩の自動処理と、ログオン時のサーバー起動を登録
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-app-tasks.ps1
# 外出先から（PCとスマホにTailscaleを入れて同じアカウントでログイン後、PCで1回）
tailscale serve --bg 8765
```

## 9. 制約・注意

* PCが起動している必要があります（タスクは「スリープを解除して実行」を設定）。
* netkeibaへの通信は既存の取得間隔（10秒）を守ります。地方を含む1日分の成績収集は20〜30分、全レースの出馬表取得も同程度かかります。
* prepareは全期間の作り直しなので時間がかかります（毎晩の処理全体で1〜2時間を想定）。将来、追記方式に置き換えられる作りにしておきます。
* モデルは仮版です。血統などでモデルを改良しても、画面・記録・自動処理はそのまま使えます（モデルの差し替えだけ）。
